# e2e.run - E2E

Group `e2e`. Central workflow: `.github/workflows/e2e.run.yaml`.

## Purpose

Runs the repository's own end-to-end suite for **one** version of the service the project is tested
against (for example a Garage or Pocket-ID release). What the suite does, and how it starts the service,
is defined by the repository in its `ci:e2e` mise task; this workflow only installs the tools and runs it
with `E2E_VERSION` set. Job `e2e`, displayed as `E2E (<version>)`.

There is **one caller file per version**, because GitHub status badges are per workflow file, not per
matrix leg. These callers are created by [e2e.sync](e2e.sync.md).

## When it runs

Caller `merge_group,pull_request,push.e2e-<version>.yaml`, on `merge_group`, `pull_request` and `push`
to the default branch.

## Inputs

| Input     | Type   | Default | Notes                                                                          |
| --------- | ------ | ------- | ------------------------------------------------------------------------------ |
| `version` | string | -       | **Required.** The exact version, exposed to the task as `E2E_VERSION` (e.g. `v2.3.0`). |

## Secrets

None.

## Permissions (granted by the caller)

`contents: read`

## Required mise tasks

`ci:e2e` (required; reads `E2E_VERSION`). See [Mise-Tasks](Mise-Tasks.md).

## Example caller

Generated by [e2e.sync](e2e.sync.md) from `.github/templates/e2e-caller.yaml.tmpl` (banner omitted):

```yaml
name: E2E (v2.3.0)

on:
  merge_group: {}
  pull_request: {}
  push:
    branches: [main]

concurrency:
  group: ${{ github.workflow }}-${{ github.event.pull_request.number || github.ref }}
  cancel-in-progress: true

# Minimal top-level permissions - each job declares what it needs.
permissions: {}

jobs:
  e2e:
    name: 🧪 E2E (v2.3.0)
    # Pinned to the axnic/.github commit that last changed this workflow; Terraform keeps it up to date.
    uses: axnic/.github/.github/workflows/e2e.run.yaml@<commit-sha> # main
    with:
      version: v2.3.0
    secrets: inherit
    permissions:
      contents: read
```

## Known limitations

- The template is generic (the job name is `E2E (<version>)`). A hand-written caller with another banner
  or job name differs from what the sync generates, and must be regenerated from the template to match it.
